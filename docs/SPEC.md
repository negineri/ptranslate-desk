# PTranslate Desk 仕様 (SPEC)

PTranslate Desk は、このリポジトリのサーバー (`server/`) を裏側にして、デスクトップアプリとして使えるクライアント。
Web 版の名前は PTranslate。
このファイルだけを読めば実装を始められるように書く。

Windows・macOS向けのローカル翻訳の導入・デバイス選択・メモリ管理は[ローカルモードの仕様](LOCAL_TRANSLATION.md)に記載する。
初回はモードを選び、既存設定がある場合は引き継ぐ。以下のサーバー・認証の記述はサーバーモードに適用する。

この仕様の中の「サーバー」は、認証プロキシ (nginx + oauth2-proxy) の後ろで動く `server/translator.py`を指す。

「翻訳エンジン」は PLaMo 3 Translate を動かす llama-server を指す。サーバーモードのクライアントは翻訳エンジンに直接つながず、
必ずサーバーを通す。本番のサーバーは `https://translate.witenp.com/`、ログインは Authentik
(`https://atk01.witenp.com/`)。そのデプロイの設定は別の (非公開の) リポジトリにある。

## 1. 目的と範囲

### やること

- どのアプリで選んだ文でも、ショートカット 1 つで訳して、翻訳ポップアップに出す
- 文章を貼って訳すメインウィンドウ (Web の画面と同じ機能: 言語、文体、文脈、用語集、自動で翻訳)
- タスクトレイ (macOS はメニューバー) に常駐する
- サーバーモードではAuthentik のアカウントでログインする (SSO)。VPN は要らない
- Windows・macOSのローカルモードでは、この端末でモデルを動かして翻訳する。モデル取得後の翻訳にログインや通信は要らない

### やらないこと

- 画像やファイル (PDF、Office) の翻訳。OCR
- サーバーモードでの翻訳エンジンの直接の呼び出し。PFML3 (翻訳エンジンの素の書式) の組み立てはサーバーが行う
- 利用者の操作の送信 (テレメトリ)。クラッシュの報告も送らない

### 対象

| OS      | 版                                     | 備考                                                                                                 |
| ------- | -------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Windows | 10 / 11 (x64)                          |                                                                                                      |
| macOS   | 13 以降 (Apple Silicon と Intel)       | アクセシビリティの許可が要る (選んだ文の取得)                                                        |
| Linux   | X11 のデスクトップ (Ubuntu 24.04 以降) | Wayland ではショートカットの横取りと選んだ文の取得ができない。メインウィンドウとトレイだけ動けばよい |

## 2. 技術の選択 (推奨)

- **Tauri 2** (Rust + Web の画面)。Electron より配布物が小さく、ショートカット (`global-shortcut`)、クリップボード
  (`clipboard-manager`)、トレイ、自動更新 (`updater`)、OS の資格情報の保管 (`keyring` 相当) の部品がそろっている
- 画面は TypeScript。サーバーの Web の画面 (`index.html`) の見た目と言葉に合わせる (日本語の UI)
- HTTP とストリーミングは Rust 側 (`reqwest`) で行い、画面へはイベントで渡す。ブラウザの `fetch` を使わないので
  CORS は関係しない

別の技術を選ぶときも、この仕様の動き (4〜8 章) を満たすこと。

## 3. 画面と操作

### 3.1 翻訳ポップアップ (選んだ文の翻訳)

1. 利用者がどこかのアプリで文を選び、ショートカット (既定は **Ctrl+C を 0.5 秒以内に 2 回**、macOS は ⌘C を 2 回。
   設定で任意の修飾キーと文字の組み合わせにも変えられる。他のアプリと重なる場合は別の組み合わせを指定する) を押す
2. クライアントは選んだ文を取る。取り方は次の順に試す
   - Ctrl+C を 2 回押す方式なら、その操作でクリップボードに入った文をそのまま使う
   - 組み合わせのショートカットなら、Ctrl+C (⌘C) を送って選んだ文をクリップボードに写し、読んだら
     クリップボードを元に戻す (戻すのは文字列だけでよい)
3. 翻訳ポップアップは幅 600 論理ピクセルを基本とし、訳文の行数に応じて高さを変える。開いたときのマウス位置を基準に配置し、画面の作業領域の四辺に余白を残して収める。画面より長い訳文は訳の欄でスクロールする。
   マウスの近くに翻訳ポップアップを出し、すぐに訳し始める (4.3 の「自動で翻訳」と同じ流れ、待ちは 0 秒)
4. 翻訳ポップアップには、原文の言語と訳す先 (5 章)、訳 (届いた分から出す)、**コピー**、**メインウィンドウで開く**、**閉じる** を置く
5. 翻訳ポップアップは、Esc、外を押す、閉じるボタンで消える。消したら翻訳を止める (5.4)
6. 訳す先はメインウィンドウと共有の設定。既定は「日本語 ⇄ 英語 (自動)」

### 3.2 メインウィンドウ

翻訳の操作はサーバーの Web の画面と共通。デスクトップでは「翻訳」「設定」のタブで切り替える。
画面上部にアプリ名、バージョンと更新操作、利用者名とログイン・ログアウトをまとめる。
バージョン表示から更新メニュー、利用者名からログアウトを開く。
配布バージョンはビルド対象のHEADに付いた `v*` のgitタグから取得する。通常のローカルビルドはデバッグ版で、
バージョンは `0.0.0-dev` とする。タグのあるコミットでも配布ビルドを明示しなければ開発版とする。
接続先・デスクトップの設定・キーチェーンの説明は「設定」に置き、ログイン前も操作できる。
起動時は未ログインなら「設定」、ログイン状態を復元できた場合は「翻訳」を初期表示する。
切り替えても入力中の原文と訳文を保持する。トレイの「設定」は設定タブを開き、ポップアップからの引き継ぎは翻訳タブを開く。

- 左に原文、右に訳。原文の言語 (「自動で判定」か 53 言語)、訳す先 (「日本語 ⇄ 英語 (自動)」か 53 言語)、
  訳す先が日本語のときの文体 (おまかせ / です・ます / だ・である)、入れ替え (⇄)
- 「自動で翻訳」(既定でオン)。入力が止まって 1 秒たつと訳す。オフなら「翻訳する」(Ctrl+Enter)
- 「中止」「空にする」「訳をコピー」、文字数
- 「詳しい設定」に文脈 (訳さない参考の文) と用語集 (1 行に 1 つ「原語 => 訳語」。`=>`、`⇒`、`→` を区切りに読む)
- 長すぎて切れた区切りがあれば、その数を出す (5.3 の `finish: "length"`)

### 3.3 トレイ

- メニュー: メインウィンドウを開く / ショートカットを一時的に止める / 設定 / ログアウト / 終了
- ログインしていなければ、トレイのアイコンを変え、メニューの先頭を「ログイン」にする

### 3.4 設定

| 設定                        | 既定                                         | 保存先                                                               |
| --------------------------- | -------------------------------------------- | -------------------------------------------------------------------- |
| ショートカット              | Ctrl+C を 2 回                               | 設定ファイル                                                         |
| 訳す先・原文の言語・文体    | 日本語 ⇄ 英語 (自動) / 自動で判定 / おまかせ | 設定ファイル                                                         |
| 用語集                      | 空                                           | 設定ファイル                                                         |
| 自動で翻訳                  | オン                                         | 設定ファイル                                                         |
| OS にログインしたら起動する | オフ                                         | OS の自動起動                                                        |
| 履歴を残す                  | オフ                                         | 設定ファイル。オンでも端末の中だけ (最新 100 件)、消すボタンを付ける |
| サーバーの URL              | 空欄（利用者が設定）                         | 設定ファイル (試験用に変えられるようにする)                          |

設定ファイルは OS の標準の場所 (Tauri の `app_config_dir`)。トークンは設定ファイルに書かない (6.3)。

## 4. 訳し方 (クライアントの中の動き)

### 4.1 区切り

翻訳エンジンは、原文が長いと繰り返しに入る。サーバーは 1 回あたりの原文を 4,000 文字までしか受けない。
クライアントは原文を区切り、1 区切りずつ送る。Web の画面と同じ規則にする (同じ原文なら同じ区切りになる)。

1. 原文を、空行 (改行 → 空白だけの行 → 改行、正規表現 `\n\s*\n`) で段落に分ける。区切りの空白は残しておき、
   訳の同じ位置に戻す (段落の形を保つ)
2. 1,500 文字 (`CHUNK_CHARS`) を超える段落は、文の終わり (`。．.!?！？` と改行) で分け、1,500 文字までまとめる。
   文の終わりが無く 1,500 文字を超えるものは、1,500 文字ごとに切る
3. 短い段落は、間の空行ごと 1,500 文字までまとめて 1 区切りにする
4. 各区切りの前後の空白は送らず (`trim`)、訳の前後に元の空白を付けて並べる

### 4.2 前の訳を手がかりにする

2 つ目以降の区切りは、直前の区切りの原文と訳を `history` に 1 組だけ付けて送る (5.2)。訳語や文体がそろう。

### 4.3 自動で翻訳と、覚えておく訳

- 入力が止まって 1 秒 (`AUTO_DELAY`) たったら訳す。原文と設定が前に訳し終えたときと同じなら訳さない
- 区切りごとの訳を、鍵「設定 (訳す先・原文の言語・文体・文脈・用語集)・その区切りの原文・直前の区切りの原文」で
  覚えておく (最新 500 件)。覚えている区切りは送らずに並べる。末尾に書き足すと、足した区切りだけを送る
- 訳している途中で原文や設定が変わったら、走っている翻訳を止め (5.4)、新しい内容で訳し直す。止めたことは
  エラーとして出さない

### 4.4 訳す先の自動 (日本語 ⇄ 英語)

原文の先頭 2,000 文字のうち、文字 (Unicode の Letter) に占めるかな・漢字 (`U+3040–U+30FF`、`U+3400–U+9FFF`)
の割合が 0.2 を超えたら英語 (`en`) へ、そうでなければ日本語 (`ja`) へ訳す。原文の言語を選んでいて訳す先と
同じなら、送らずに「原文と訳す先が同じ言語です」と出す。

## 5. サーバーの API

すべて `https://translate.witenp.com` の下。今の Web の画面が使っているものと同じで、クライアントのために
変えるのは認証 (6 章) だけ。

サーバーは利用者を、前段の認証プロキシが検証して付ける `X-Forwarded-User` で区別する。
`TR_USERINFO_URL` を設定したサーバーでは、`X-Forwarded-User` が無く前段が検証した Bearer だけがあるとき、
その token で IdP の userinfo を呼び、`preferred_username` を利用者名にする (access token にユーザー名が
入らない Pocket ID 向け)。結果は token の期限までか 5 分のうち短いほど覚える。userinfo につながらなければ 502。

### 5.1 `GET /api/config`

```json
{
  "user": "alice",
  "pool": { "kind": "direct" },
  "tier": "registered",
  "languages": [
    { "code": "ja", "name": "日本語" },
    { "code": "en", "name": "英語" },
    "..."
  ],
  "max_chars": 4000,
  "max_glossary": 200,
  "concurrency": {
    "max_in_flight": 2,
    "scope": "user"
  },
  "desktop_connection": {
    "server_url": "https://translate.example.com",
    "discovery_url": "https://auth.example.com/.well-known/openid-configuration",
    "client_id": "translator-desktop"
  }
}
```

起動時とログインの直後に読み、言語の一覧と上限を使う。言語は 53 個 (コードは
`ja en zh-hans zh-hant ko ar az be bg bn ca ceb de es et eu fa fr gu he hi hr hu hy id it jv ka kk km lt lv ml mr
ms my ne nl pa pl ru si sk sl sr sw ta te th tl ur uz vi`)。表示名はサーバーが返すものを使う。

`desktop_connection` はWeb版の「クライアントの接続設定」ボタンで表示する公開設定。
`TR_PUBLIC_SERVER_URL`、`TR_DESKTOP_DISCOVERY_URL`、`TR_DESKTOP_CLIENT_ID` から返す。
URLの既定値は空欄、client IDは `translator-desktop`。Web版はサーバーURLが空欄なら閲覧中のオリジンを表示する。
認証先が空欄のときは管理者への確認を案内し、内部のuserinfo URLや要求のヘッダーから推測しない。
既存の `/api/config` と同じ認証を必要とし、秘密鍵やトークンは含めない。

`concurrency` は未完了の翻訳要求数の上限を通知する。枠の予約ではない。
サーバーは `TR_MAX_ACTIVE_PER_USER` を `max_in_flight` に返し、`scope` は `user`（同じ利用者の全クライアントで共有）とする。
ローカルは設定した並列数の実行枠を返し、`scope` は `application`（デスクトップと拡張で共有）とする。
クライアントは通知された上限と自身の処理上限の範囲で送信する。古い接続先で通知がない場合は1件とする。
サーバーモードでは各クライアントが独立して送信するため、合計が通知された上限を超えることがある。
サーバーが利用者ごとの合計を制限し、超過した要求には429を返す。拡張は空きを待って再試行する。
ローカルではアプリ内の共通待ち行列で実行数を制限する。自動調整時に枠を減らしても実行中の要求は中断せず、
新しい要求を待たせる。モデル読み込み時に値が下がった場合、以後の設定取得で新しい値を通知する。

Chrome拡張は翻訳開始時の接続先（ローカルかサーバーか、およびサーバーURL）を保持する。
実行途中の設定変更は、その翻訳の分割・再試行・ページ更新への追従には適用しない。
設定変更後に新しく開始する翻訳から新しい接続先を使う。

`pool.kind` は現在 `direct`、`tier` は `registered` または `anonymous` を返す。
匿名のときは `user` は空文字、`max_in_flight` は1。同じ資格を使う全クライアントで上限を共有する。
複数エンジンの直結プール、待ち行列、匿名の層のサーバーAPIは実装済み。ボランティア枠は未実装で、
`TR_POOL_KIND` に `direct` 以外を指定すると起動を断る。
全体の設計と今後の実装順は [翻訳ワーカーのプールの仕様](VOLUNTEER_TRANSLATION.md) を参照。

### 5.1.1 `POST /api/anonymous`

`TR_ANON_ENABLED=1` のときだけ有効（既定は無効、無効時は404）。認証不要で、本文は `{}`、
`Content-Type: application/json` が必須。応答は `{"credential":"pta_...","expires_in":2592000}`。
資格は128bitの乱数・期限・HMAC-SHA256で構成し、30日で失効する。署名と期限だけを検証し、資格は保存しない。
`TR_TOKEN_KEY` は32バイト以上で必須。取り直し・鍵の変更・再起動によって、登録済みの認証情報を置き換えない。

発行要求の `Origin` が `TR_PUBLIC_SERVER_URL` と完全に一致すればWeb用とし、
本文から `credential` を省き、`__Host-pta` Cookieを設定する。
Originがないか `chrome-extension://` で始まる場合は本文で資格を返し、Cookieは設定しない。
それ以外のOriginは403で断る。
属性は `HttpOnly; Secure; SameSite=Strict; Path=/; Max-Age=2592000`。
Cookie認証は同じOriginの一致があれば通す。Originがない場合は、`Sec-Fetch-Site: same-origin` があり、
メソッドがGETかHEADの場合だけ通す（同一オリジンへのGETでOriginを送らないブラウザーに対応する）。
`same-site`・`cross-site`・ヘッダー欠落は403。POSTはOriginの一致を必須とし、Originがない場合は403。
OPTIONSへの対応やCORSヘッダーは追加しない。ほかのWebサイトのJSON要求をプリフライトで許可しない。
公開URLが未設定ならWeb用の発行とCookie認証は断る。公開URLはHTTPSのオリジンを指定する。
Bearerの資格を送るクライアントはOriginなし、拡張は拡張のOriginで発行し、Cookieを使わない。

発行はIPのまとまりごとに1時間5個、サービス全体では1分 `TR_ANON_ISSUE_PER_MINUTE` 個（既定100）。
前者の超過は429、後者は503と `Retry-After: 5`。発行を試みた分を全体の制限に数える。
IPは `TR_CLIENT_IP_HEADER` の値だけから取り、IPv4 /24・IPv6 /48にまとめる。IPv4-mapped IPv6はIPv4として扱う。
ヘッダーを設定したのに値がない・不正なら403。未設定ではIP単位の発行・実行制限を使わない。
前段は外からの値を消して検証済みの値に上書きし、仲介には前段からしか接続できないようにする。

`TR_COUNTRY_HEADER` と `TR_ALLOWED_COUNTRIES`（カンマ区切り、例 `JP`）で受ける国を制限する。
一覧が空なら無効。一覧がある場合は国ヘッダーも必須で、欠落・対象外の要求は全パスで403、`code: "region"`。

### 5.1.2 ワーカーの登録と通信（準備段階）

`TR_STATE_FILE` と `TR_WORKER_MODEL_SHA256` を指定した場合、次のAPIを有効にする。
未設定なら404。直結プールの翻訳をワーカーへ渡す経路はなく、ボランティア枠の起動も引き続き断る。
確認用ジョブによる試用・検疫は任意で有効にできる。利用者ジョブとの接続・分散、抜き取り検査、クライアント画面は未実装。
検査を未設定の場合、ポーリングは割り当てなしで204を返す。設定済みの場合は運営の合成ジョブだけを渡す。

| API | 認証・動き |
| --- | --- |
| `POST /api/worker/register` | 前段のOIDCヘッダー必須。`{"terms_version":1}` を送り、`worker_id`・`secret`・`expires_in:604800` を返す。秘密は一度だけ返す |
| `POST /api/worker/renew` | 所有者のOIDC必須。`{"worker_id":"..."}` を送り、有効期限を現在から7日後へ延長。秘密は変えず再送しない |
| `GET /api/worker/mine` | 所有者のOIDC必須。`{"workers":[{"worker_id":"...","state":"probation","expires_at":1234567890}]}` を返す |
| `DELETE /api/worker/<worker_id>` | 所有者のOIDC必須。登録を削除し `{"deleted":true}`。最後の端末の削除時は同意の記録も削除する |
| `POST /api/worker/poll` | ワーカーのBearer資格必須。`agent_version` と `model`（モデルのSHA-256）を確認し、最大25秒待つ。空なら204。同時ポーリングと実行中の再ポーリングは409 |
| `POST /api/worker/result` | ワーカーのBearer資格必須。割り当てID・連番・断片・終了を受ける。通信の詳細はボランティア仕様9章 |
| `POST /api/worker/ping` | ワーカーのBearer資格必須。`{"active":["割り当てID"]}`（最大1件）に `{"stop":["停止するID"]}` を返す |

管理APIでは `X-Forwarded-User` だけを受け、匿名資格やワーカー資格だけでは登録・更新・解除できない。
ワーカー資格は `ptw_` と256bitの乱数（小文字16進数）。利用者のAPIには使えず、userinfoにも送らない。
1所有者2台（`TR_WORKERS_PER_OWNER`）、規約の版は1。
登録前に所有者の期限切れ端末（失効以外）を削除して上限を数え直す。`mine` は期限切れ端末を返さない。新規登録は `probation`（試用）から始める。
状態は試用・検疫 (`quarantine`)・失効 (`revoked`)。確認用ジョブに連続合格した端末は一覧で `ready`（合格済み）と表示する。
合格済みでも現段階では利用者ジョブを受けず、空のポーリングは204で終える。

資格のSHA-256・所有者・期限・状態、所有者の規約の版と同意日（UTCの日）だけをSQLiteに保存する。
POSIXでは親ディレクトリは0700、ファイルは所有者本人の0600とし、シンボリックリンクと通常ファイル以外を断る。
資格そのもの、割り当てID、入力・訳、IPは保存・記録しない。失効・検疫は再起動後も維持する。
運営向けの内部処理で端末の状態変更と所有者の失効ができる。所有者の失効では端末を削除し、所有者名と失効状態だけ残す。
運営用のHTTP APIは追加しない。`tools/worker_admin.py` は別プロセスで `TR_STATE_FILE` を開き、
所有者一覧、所有者・ワーカーの失効、所有者全体の検疫解除を行う。待機中のポーリングには次の5秒ごとの資格再確認で失効が反映される。

`TR_WORKER_MODEL_SHA256` は承認するモデルの小文字16進数64桁。`TR_MIN_AGENT_VERSION` は数値3つの版で、
空なら `0.0.0`。SHA-256と版の申告は信用の根拠にせず、検査の実装を省略しない。
ポーリング中の資格のDB再確認は5秒ごととし、Hubの割り当て用ロックの外で行う。
資格の期限に達した場合も更新の有無をDBで確認する。失効したワーカーID・所有者はメモリの集合でも管理し、
失効・解除のDB処理後に待機中のポーリングを起こす。ループは毎周その集合を確認し、再確認の時刻を待たず401で終える。
前段はポーリング・結果・pingの3つだけを完全一致でOIDCから除外し、各場所でクライアントの
`X-Forwarded-User` を消す。登録・更新・一覧・解除はOIDCを通す（構成例は SELF_HOSTING.md）。
ワーカー向けPOSTはJSON・本文64KiBまで。割り当てを持つワーカーの不正な本文は、その割り当ても失敗にする。
全APIに国の制限を適用する。CORSやOPTIONSへの対応は追加しない。

### 5.1.3 確認用ジョブと検疫

ワーカー設定に加えて `TR_AUDIT_UPSTREAMS` と `TR_CANARY_FILE` の両方を指定すると、起動時に検査を有効にする。
一方だけ、設定・入力が不正、またはファイルが読めない場合は起動を断る。
検証用エンジンの設定は `TR_UPSTREAMS` と同じJSON配列（`url` と `slots`）。
確認用ファイルはSPEC 5.2の翻訳要求のJSON配列で、1〜10,000件・16MiB以下、POSIXでは所有者本人だけが読める0600。
シンボリックリンクは使わず、利用者・文書の識別子やプロンプトは入れない。本番の文の集まりをリポジトリに置かない。

検査は `TR_AUDIT_UPSTREAMS` の `slots` の合計まで並列に実行する。
基準の準備中から端末と文を予約し、同じ端末に同時に2本渡さず、同じ所有者の文も重複させない。渡す直前に運営のエンジンで基準を生成し、対象のワーカーへ9章のJSONと同じ形で割り当てる。
基準生成の失敗・空の訳・長さでの終了・文字種の不一致はワーカーの成績に数えない。基準の生成は最大120秒。
同じ所有者へ同じ原文を出さないよう、使用済み原文のハッシュをメモリに持つ。再起動時にはこの集合も消える。
原文が重複した項目は最初の1件だけを使う。文が尽きた所有者には再送せず、待機させる。
運営は文を定期的に入れ替える。仲介はファイルの更新を約1秒ごとに確認し、全体を検証して再起動なしで読み直す。
不正な更新では直前の文を使い続け、再読み込みでも使用済み集合と成績を保持する。
起動時と1分ごとに今の文を使い切った所有者の数を記録し、名前は記録しない。

照合はボランティア仕様10.3に従い、NFKC・大小文字・空白をそろえた文字2つ組のDice係数（0.6以上）、
原文・用語集・基準に含まれないURL・メール、基準にない数字、訳す先の文字種を検査する。
数字は全角と半角・カンマの桁区切りをそろえる。20文字未満の文字からなる訳は文字種を判定しない。
文字種は言語ごとの文字体系の割合が20%以上を暫定の基準とする。形式・言語の判定は完全ではなく、実測でしきい値を調整する。

`TR_PROBATION_JOBS`（既定20）回の連続合格で試用・端末単独の検疫から合格済みになる。
不合格1回で端末を検疫する。通信失敗・期限切れは不合格と分け、直近20件のうち最低10件を測り、
失敗の割合が50%以上なら検疫する。合格数・失敗数・時刻・連続合格数はメモリだけで、再起動後は試用からやり直す。
同じ所有者で24時間内に3回不合格になれば、その所有者の全端末を検疫する。この状態はSQLiteに残し、新規登録にも適用する。
自動では失効しない。所有者全体の検疫は運営が `tools/worker_admin.py release-owner <name>` で解除し、全端末の試用をやり直す。
状態の世代をSQLiteで進め、解除前の連続合格数や不合格の窓を引き継がない。
検疫中でも運営の判断を待つ所有者には新しい確認用ジョブを渡さない。端末の失効を検査結果で取り消すことはない。
旧状態ファイルには所有者の検疫フラグと状態の世代を追加し、原文・訳・基準・成績は保存しない。

現段階は試用と検疫の確認用ジョブだけを自動実行する。合格後の確率的な確認用ジョブ、利用者ジョブの抜き取り、
未抽出ジョブの検査・集計ログ・分散は未実装で、`TR_CANARY_RATE` と `TR_AUDIT_RATE` はまだ使わない。
合格後の乱数による確認用ジョブと配信後の抜き取り再実行が揃うまで、利用者のジョブをワーカーへ渡さない。
`TR_POOL_KIND=volunteer` の起動制限は維持する。

### 5.2 `POST /api/translate`

要求 (`Content-Type: application/json` が必須。ほかは 415):

```json
{
  "text": "訳す原文 (前後の空白を除いた 1 区切り)",
  "target_lang": "en",
  "source_lang": null,
  "form": null,
  "context": "訳さない参考の文 (空文字でよい)",
  "glossary": [{ "source": "管理画面", "target": "dashboard" }],
  "history": [{ "source": "直前の区切りの原文", "target": "その訳" }]
}
```

| 項目          | 規則                                                                                  |
| ------------- | ------------------------------------------------------------------------------------- |
| `purpose` | 任意。`interactive` (既定)、`page_visible`、`page_rest`。優先順のヒント |
| `group` | 任意。22〜128 文字の base64url の乱数。URLやタイトルから作らない。直結プールでは形式の確認だけ行う |
| `text`        | 必須。1〜4,000 文字。空白だけは 400                                                   |
| `target_lang` | 必須。5.1 のコード                                                                    |
| `source_lang` | `null` (自動で判定) か 5.1 のコード                                                   |
| `form`        | `null`、`"polite"`、`"plain"`。`target_lang` が `ja` のときだけ (ほかは 400)          |
| `context`     | 任意。12,000 文字まで                                                                 |
| `glossary`    | 任意。200 件まで。原語と訳語はそれぞれ 200 文字まで。空の組は無視される               |
| `history`     | 任意。4 組まで (クライアントは 1 組だけ送る)。原文は 4,000 文字、訳は 12,000 文字まで |
| 全体          | 文脈・前の訳・用語集・原文を合わせて約 12,000 文字まで (超えると 413)                 |
| 共通          | どの文字列にも `<\|plamo:` を含めない (400)                                           |

応答 (成功): `200`、`Content-Type: text/event-stream`。Server-Sent Events で、行は次のどれか。

| 行                                         | 意味                                                                                          |
| ------------------------------------------ | --------------------------------------------------------------------------------------------- |
| `data: {"t": "訳の断片"}`                  | 届いた分。順に足していく。先頭の空白は画面に出すときに除く                                    |
| `data: {"done": true, "finish": "stop"}`   | 訳し終わった。最後の行                                                                        |
| `data: {"done": true, "finish": "length"}` | 長すぎて途中で切れた (翻訳エンジンが繰り返しに入ったか、上限に達した)。訳は途中まで。最後の行 |
| `data: {"error": "メッセージ"}`            | 翻訳エンジンが失敗した。メッセージは日本語でそのまま出せる。最後の行                          |
| `: ping`                                   | 待っている間の生存確認 (15 秒ごと)。無視する                                                  |

`done` か `error` が来る前に接続が切れたら、「接続が途中で切れました」として扱う。

応答 (失敗): `{"error": "日本語のメッセージ"}` を、次の状態で返す。
ただし本番の認証プロキシが返す **403 は nginx の HTML**。403 の本文は JSON として読まず、
状態の番号だけでログインし直させる。

| 状態            | 意味                                                  | クライアントのすること                                                           |
| --------------- | ----------------------------------------------------- | -------------------------------------------------------------------------------- |
| 400             | 入力が不正                                            | メッセージを出す                                                                 |
| 401             | ログインしていない (トークンが無い・切れた)           | トークンを更新し (6.2)、だめならログインし直させる                               |
| 403             | トークンが受け付けられない                            | ログインし直させる                                                               |
| 413             | 長すぎる                                              | メッセージを出す (4.1 の区切りなら普通は起きない)                                |
| 415             | Content-Type が違う                                   | 実装の誤り                                                                       |
| 429             | 同じ利用者が同時に流している翻訳が多すぎる (2 本まで) | 前の翻訳を止めてから送り直す。翻訳ポップアップとメインウィンドウで同時に流さない |
| 502 / 503 / 504 | サーバーか翻訳エンジンが止まっている                  | 「翻訳サーバーに接続できません」と出す。自動で送り直さない                       |

待ち行列が全体の上限に達した場合は503、`Retry-After: 5` と
`{"error": "翻訳の待ち行列が一杯です", "code": "busy"}` を返す。
待ちが `TR_QUEUE_TIMEOUT` を超えた場合は、SSEの `error` に `code: "queue_timeout"` を付けて終える。
どちらも自動では送り直さない。

### 5.3 待ち時間の目安

- 仲介はエンジンごとの実行枠を持ち、満杯なら待ち行列で待つ。待機中も `: ping` が届く。
  用途は `interactive` → `page_visible` → `page_rest` の順。同じ優先度では登録済み4件対匿名1件の順で処理し、同じ層では利用者を順に回す。
  匿名の実行枠は、登録済みの待ちがある間は `max(1, floor(全枠 × TR_ANON_SHARE))`（既定0.5）まで。
  登録済みの待ちがなければ空き枠を借りられる。既に実行中の匿名要求は中断しない。
  匿名は同じIPのまとまりで同時に4本まで実行し、超える分は待つ。
  待ちが `TR_AGING_SECONDS` を超えたら優先度を1段だけ上げる（それ以上は上げない）。ページ翻訳は同じ利用者の全タブで同時に1本まで。
  利用者ごとの未完了数には待機中も含め、既存の `TR_MAX_ACTIVE_PER_USER` の上限を適用する。
  ページ要求の未完了数は `max(1, TR_MAX_ACTIVE_PER_USER - 1)` までとし、超える要求は429で断る。
  対話要求は全用途の合計が `TR_MAX_ACTIVE_PER_USER` に達するまで受け付ける。
  匿名は用途によらず資格ごとに未完了1本まで。利用者ごとの待機数は登録済み8件・匿名4件までで、
  これらは未完了数の制限も同時に適用する（待機数の上限で未完了数は緩めない）。
  原文の送信量は1時間で登録済み600,000文字・匿名100,000文字まで。超過は429。
  発行数・文字数のカウンターはメモリだけで、期限が来たものを次の集計時に削除する。
  秒単位でまとめるため期限は最大1秒長くなる。文字数カウンターは登録済みと匿名を分離し、
  それぞれ10,000キーまで保持する。匿名側の満杯は登録済みに影響しない。他の各カウンターも10,000キーまでで、
  満杯なら既存の制限を消さず、新しいキーへの要求を503で断る。
  未完了数は上流の終了処理後に減らし、待ち行列が満杯の場合や処理スレッドを開始できない場合にも枠を残さない。
- `TR_UPSTREAMS` は `[{"url":"http://127.0.0.1:8080/v1/completions","slots":4}]` の形式。
  空なら従来の `TR_UPSTREAM_URL` を `TR_UPSTREAM_SLOTS` 枠（既定4）で使う。空きのあるエンジンを順番に選ぶ。
  `TR_QUEUE_TIMEOUT` は120秒、`TR_AGING_SECONDS` は30秒、全体の待機数 `TR_MAX_QUEUE` は256件が既定。
  これらは正の整数、`slots` と `TR_UPSTREAM_SLOTS` は1〜1000。
  `TR_UPSTREAMS` を指定した場合、`TR_UPSTREAM_SLOTS` は使用・検証しない。設定が不正なら起動を断る。
  枠がエンジンの並列数を超える分はエンジン側で順番を待つ。
  起動ログにはエンジンの数と枠の合計を出し、エンジンのURLは出さない。
- 1 区切り (1,500 文字) は数秒〜十数秒。読み取りの時限は 120 秒にする (ping が来ればそのたびに延ばす)

開いた接続は `TR_MAX_OPEN_REQUESTS`（既定1000）まで。超過は503と `Retry-After: 5` を返して閉じる。
各接続の要求読み取りの時限は120秒。匿名の資格とIPはログに出さず、直結プールの匿名要求は利用者欄を
固定の `anonymous` として長さ・言語・状態だけを記録する。登録済みの既存ログは維持する。
500のログにはメソッド、既知のルートのパス、例外の型だけを記録し、メッセージとスタックトレースは出さない。
クエリーは記録せず、未知のパスは `<unknown>` に置き換える。

### 5.4 止める

翻訳を止めるときは、その HTTP の接続を閉じる。
サーバーは原文の受信後、上流が無応答の間も約100ms間隔でクライアントの切断を確認する。
切断を検知すると翻訳エンジンへのソケットをshutdownし、HTTP応答ヘッダーや訳文の読み取り待ちも解除する。
接続確立後には中止済みか再確認し、中止済みなら新たに翻訳を依頼しない。
上流のTCP/TLS接続の時限は最大5秒、確立後の読み取り時限は `TR_UPSTREAM_TIMEOUT` とする。
利用者の同時実行枠は上流通信の終了処理が完了してから返す。中止直後に枠が残る場合は429になる。
サーバーが接続を閉じた後、実際の推論を止める処理は翻訳エンジン側の切断検知に従う。

## 6. 認証

### 6.1 方式

接続先はメインウィンドウの「サーバー翻訳の設定」で、ログイン前から変更できる。
サーバーURL（HTTPSのオリジン）、OIDC discovery URL（HTTPS）、公開クライアントのclient IDを指定する。
初期値はサーバーURL・OIDC discovery URLを空欄、client IDを `translator-desktop` とする。
接続先が未設定の間は認証情報の復元や認証先への通信を行わず、ログイン時は設定を案内する。
ユーザー情報・クエリー・フラグメントをURLに含めず、サーバーURLにはパスを付けない。
以下の本番サービスの値は既定値であり、独自サーバーでは置き換える。
「適用」はログイン処理中には受け付けず、進行中のサーバー翻訳を止め、旧接続先からログアウトする。
端末の資格情報を削除・revokeしてから公開設定を `connection.json` に保存し、起動中のサーバー接続を差し替える。
書き込みは一時ファイルから置き換え、不正な保存済み設定では起動を止める。

Authentik (`https://atk01.witenp.com/`) の OAuth2 / OIDC。**公開クライアント (client secret を持たない) の
Authorization Code + PKCE (S256)**、リダイレクトは **ループバック** (`http://127.0.0.1:<空いているポート>/callback`)。

1. クライアントは 127.0.0.1 の空いているポートで一時的に待ち受け、OS の既定のブラウザで authorize の URL を開く
   - `client_id`: `translator-desktop`
   - `scope`: `openid profile offline_access` (`email` は入れない)
   - `redirect_uri`: `http://127.0.0.1:<port>/callback`
   - `code_challenge` / `code_challenge_method=S256`、`state`
2. 利用者がブラウザで Authentik にログインする (既にログインしていれば画面はすぐ戻る)
   - 初回は Authentik の同意の画面が出る。これが正常な動き
3. コールバックで `state` を確かめ、token の URL で code をトークンに替える
4. ブラウザには「ログインしました。このタブは閉じて構いません」を返す

URL は OIDC の discovery (`https://atk01.witenp.com/application/o/translator-desktop/.well-known/openid-configuration`)
から取る。決め打ちにしない。

### 6.2 トークンの使い方

- API には `Authorization: Bearer <access token>` を付ける。access token は Authentik が署名した JWT で、
  有効期限は本番では 10 分、refresh token は 30 日
- `email` を scope に入れると、oauth2-proxy が `email_verified: false` を理由に 403 で断るため、要求しない
- 期限の 1 分前か、401 を受けたら refresh token で更新する。更新に失敗したらログインし直させる
- 起動したときに refresh token があれば、黙って更新してログイン済みにする

### 6.3 保管

- refresh token は OS の資格情報の保管 (Windows の資格情報マネージャー、macOS のキーチェーン、Linux の Secret Service)
  に置く。ファイルに書かない。access token はメモリだけ
- ログアウトで消す (discovery に `revocation_endpoint` があれば revoke も呼ぶ。Pocket ID のように無い IdP では
  端末から消すだけで、サーバー側の refresh token は有効期限まで残る)
- refresh tokenの保存項目はサーバーURL・discovery URL・client IDの組ごとに分離し、別の接続先で再利用しない。
  既定の接続先では従来の保存項目を維持する。変更した接続先への初回アクセスには保存済みトークンを使わない
- macOSのメインウィンドウでは、キーチェーンを使う前に、ログイン状態を保つ認証情報へのアクセス確認が
  出る場合があることを案内する。対象がPTranslate Deskと `com.witenp.ptranslate-desk` であることを確認し、
  キーチェーン「ログイン」のパスワード（通常はMacのログインパスワード）をOSの確認画面に入力して
  「常に許可」を選ぶ手順を示す。更新・差し替え後は再確認される場合があることも伝える

### 6.3.1 匿名の資格

匿名の層に対応するクライアントは、発行された資格をデスクトップではOSの資格情報の保管、拡張では
`chrome.storage.local`（syncは使わない）に置き、接続先ごとに分けてBearerで送る。
WebはHttpOnly Cookieを使う。期限切れ・401では取り直し、捨てるときは端末から消す。
今回の実装はサーバーAPIまでで、既存クライアントの匿名ログイン画面は未実装。

### 6.4 使える人

Authentik の `tamesareru-members` だけ (Web と同じ)。入っていない人は Authentik の画面で断られる。
これは既定の本番サービスの制約。独自サーバーでは管理者が自分のAuthentikで利用者・グループとアプリの許可を設定する。
構築方法は [自分のサーバーで使う](SELF_HOSTING.md) を参照。

## 7. 配布と更新

- 配布物: Windows は MSI か NSIS、macOS は universal (`universal-apple-darwin`) の dmg、Linux は AppImage と deb
- 署名: macOS は Apple の Developer ID で署名と公証、Windows はコード署名 (無ければ SmartScreen の警告が出ることを
  README に書く)。署名の鍵はクライアントのリポジトリの CI の秘密に置く
- Developer IDを用意するまでは、macOSの署名・公証は保留する。Releaseの説明に
  「署名していないので、初回は右クリックから開く」と書く
- 更新: Tauri の updater。更新の情報 (JSON) と配布物は、このリポジトリ (公開) の GitHub Releases に置く。
  起動時と 1 日 1 回確かめ、利用者が承認してから入れる
- 更新用の秘密鍵とパスワードはActions secrets、公開鍵は `tauri.conf.json` に置く。
  `latest.json` はApple SiliconとIntelの両方に同じ署名付きuniversal更新ファイルを割り当てる。
  Windows x64には `windows-x86_64` として更新署名付きNSISインストーラーを割り当てる。
  3プラットフォームの配布物・更新署名を検証し、共通のReleaseとして一度に公開する。
- Windowsコード署名は当面付けない。READMEとReleaseの説明に未署名であることとSmartScreenの警告が出る場合があることを書く。
  Tauriの更新署名は省略しない。Windowsでは利用者の承認後、インストール時にアプリを終了し、完了後に起動し直す
- `v*` タグと `tauri.conf.json` の `version` を一致させ、サーバーイメージと同じタグで配布する。
  mainとPRはActionsの成果物だけを作る。手順は [RELEASING.md](RELEASING.md) を参照

## 8. 守ること

- 原文・訳・用語集を、サーバー以外に送らない。履歴は既定で残さない (3.4)
- ログ (端末の中) にも原文と訳を書かない。書くのは時刻・言語・長さ・状態だけ
- サーバーの URL は https だけ。証明書の検証を外す設定を作らない
- 選んだ文を取るためにクリップボードを使ったら、元に戻す (3.1)

## 9. 署名と未決定の事項

macOSの配布版は固定の自己署名証明書を継続利用し、Bundle IDと証明書による識別条件を更新前後で維持する。
アドホック署名からの初回移行時はアクセシビリティの許可を再登録する。ローカルの開発版は配布用の秘密鍵を使わない。
秘密鍵はGPG暗号化したバックアップとCIのActions secretsで管理し、公開証明書だけをリポジトリへ置く。
GPG秘密鍵をCIへ渡さない。AppleのDeveloper IDと公証は未対応。
Tauri更新署名鍵はmacOSコード署名鍵と分けてGPG暗号化バックアップに保存する。更新ファイルと版の署名を
アプリの公開鍵で検証してから公開する。旧更新署名鍵を失った場合、新しい公開鍵を含む版を手動インストールする。

| 項目                 | 選択肢                                                      |
| -------------------- | ----------------------------------------------------------- |
| 署名                 | Apple の Developer ID と Windows の署名の証明書を用意するか |
| ショートカットの既定 | Ctrl+C を 2 回 か、組み合わせか                             |
| Linux の Wayland     | メインウィンドウとトレイだけでよいか                        |

## 10. 受け入れの条件

| #   | 条件                                                                                                                          |
| --- | ----------------------------------------------------------------------------------------------------------------------------- |
| 1   | Windows・macOS・Linux (X11) で、ほかのアプリで選んだ日本語の文を、ショートカットで英語に訳して翻訳ポップアップに出せる        |
| 2   | 翻訳ポップアップで訳が届いた分から出る。Esc で閉じると、サーバーの翻訳も止まる (サーバーのログが `finish=canceled`)           |
| 3   | メインウィンドウで、自動で翻訳・中止・空にする・入れ替え・文体・文脈・用語集が Web の画面と同じに動く                         |

| 5   | 末尾に段落を足すと、足した区切りだけを送る                                                                                    |

| 7   | `tamesareru-members` に入っていない人は使えない                                                                               |
| 8   | 429・401・502 を受けたときに、5.2 の表のとおりに動く                                                                          |

## 11. 試験のためのモック

翻訳エンジンにつながずに試せるよう、クライアントのリポジトリに 5 章の API のモックを置く。`/api/config` と
`/api/translate` (SSE) を返し、受けた区切りの数を数え、遅延・`finish: "length"`・`error`・429・401 を返せるように
する。認証は、モックでは `Authorization` を確かめない設定で試す。
