# ローカル翻訳 (Windows x64 / macOS)

翻訳サーバーなしで、この端末のPLaMo 3 Translate 2Bを使えます。
デスクトップアプリがllama.cppの`llama-server`を子プロセスとして管理します。
サービスの登録、CUDA/Vulkan SDKの導入は行いません。通常のサーバーモードも選べます。

## 初回の設定

初回起動時に「このPCで翻訳」と「サーバーで翻訳」を選びます。
既に接続先やローカルモードを設定済みの場合は、その設定を引き継ぎます。

1. 「このPCで翻訳」を選ぶ。
2. モデルがない場合は「モデルをダウンロード」を押し、容量と取得元を確認して「ダウンロードする」を押す。
   モデル約1.81 GBと推論エンジン（Windows約37 MB、Mac約12〜16 MB）を取得する。空き容量の目安は約2 GB。
3. ダウンロード中はファイルごとの取得量と割合を表示する。中止でき、失敗時はやり直せる。
4. 取得後は短い文章でGPUとCPUを順番に計測し、速い候補を「おすすめ」として表示する。
   モデル読み込み時間を除く短文翻訳の時間を比べる。各デバイスは最大45秒。
   続いて短文で最速だったGPUで、ページ翻訳に近い短文の負荷で並列数を計測し、求めた値を補正せず推奨する。CPUの並列数は計測しない。
   GPUがない、またはGPUの短文計測に成功しなかった場合は、並列数の計測を行わない。
5. 計測結果を表示し、推奨デバイスと並列数を設定欄へ自動入力する。ウィンドウ右上の「適用」で反映する。ログインや接続先の設定は不要。
   最速の短文計測デバイスを選び、そのGPUの並列数の推奨値を使う。CPUや並列計測に成功しなかったGPUでは1並列とする。

デバイスと並列数は設定欄から変更できます。計測を中止した場合は入力済みの値を保持します。
計測後に翻訳モードを切り替えて戻しても再計測せず、結果と入力値を保持します。
保存済みの計測完了状態と、以前の版で保存した明示的なデバイス設定も引き継ぎます。再計測は「計測して候補を確認」で行います。
計測結果だけで設定は保存しません。長文の並列計測に成功したGPUがあれば、そのデバイスと推奨並列数を設定欄に反映します。取得できない場合は短文の計測結果からデバイスを選びます。

### 大量翻訳向けの計測

- 約1,500字の合成英文12件を日本語に翻訳する。各候補で同じ12件を2回処理し、24件の総処理時間から1分あたりの処理件数を求める。空いたワーカーが次の長文を受け取り、翻訳履歴は共有しない。
- 自動計測の候補は1・2・4・8・12並列。1スロット32768トークンを維持し、候補ごとにモデルを読み直す。
  デバイス比較と並列数の各候補は、起動前にモデル・KVキャッシュ・作業領域を見積もる。見積もりに10%（最低512 MiB）の余裕を加え、空き容量を確認する。macOSではGPUとホストが共有するシステムメモリも確認する。
  容量が足りない場合や確認できない場合はその候補を起動せず、理由を表示する。並列数の計測はそこで止め、完了した候補を使う。
  読み込みとウォームアップは速度に含めない。プロンプト生成・HTTP要求・ストリーミングの読み取りは実際のローカル翻訳と共通の処理を使い、キャッシュも本番と同じ既定の動作にする。空の訳や出力上限による未完了は成功に数えない。
- 結果には完了した候補ごとの処理速度と、モデル・KVキャッシュ・作業領域の合計見込みを表示する。表示値には空き容量チェック用の余裕分を含めない。macOSでは共有メモリの合計、WindowsではRAMとVRAMを別々に表示する。
- 完了した候補の最高速度の95%以上を出せる最小の並列数を求める。
  8並列以降で、過去最高からの改善が5%未満の候補が2回続いたら打ち切る。
  全候補・全文章での最適値を保証するものではなく、独立した長文をまとめて処理する負荷を処理する速度の目安。Chromeの中継EXE起動・ブラウザー内の通信・DOMへの描画時間は含まない。
- 並列数の計測全体は最大4分。候補の読み込みは最大45秒、ウォームアップは最大15秒、2回の翻訳は最大90秒。
  計測中は現在のデバイスと並列数を表示し、いつでも中止できる。
- エンジンの異常終了や時間切れで打ち切った場合は、完了した候補から推奨し、打ち切り理由も表示する。
  中止・エラー時も計測用エンジンと要求を終了する。完了した推奨値は設定欄へ入力するが、保存するまでは動作中の設定を変えない。

「サーバーで翻訳」を選んだ場合は接続先設定を開き、通常のログインへ進みます。
設定タブの「翻訳する場所」から、あとでモードを切り替えられます。

## モデルとメモリ

「使っていないときにモデルのメモリを自動解放する」は既定で無効です。
無効の場合は、ローカルモードでの起動直後にバックグラウンドでモデルを読み込み、そのまま保持します。
読み込み中の状態はメインウィンドウにも表示します。

自動解放を有効にすると、翻訳するときに読み込み、指定した未使用時間が過ぎると解放します。
既定は5分で、1〜60分の範囲で設定できます。解放の確認は5秒間隔です。
デスクトップとChrome拡張の実行中・待機中の翻訳、および計測中は自動解放しません。
すべての要求が終了した時点から未使用時間を数えます。中止した場合も同じです。

「モデルを読み込む」で事前に読み込むこともできます。手動の解放ボタンは設けず、
設定した未使用時間の経過またはアプリの終了時に解放します。
WindowsではJob Objectを使い、アプリが強制終了した場合にも推論プロセスを終了させます。

## 取得するファイル

llama.cpp b11804のWindows Vulkan版またはmacOS Metal版と、PLaMo 3 Translate 2BのQ4_K_M版を、固定URLから取得してSHA-256を検証します。
Windowsの保存先は`%LOCALAPPDATA%/com.witenp.ptranslate-desk/inference/`です。
macOS 13.3以降（Apple Silicon・Intel）では`~/Library/Application Support/com.witenp.ptranslate-desk/inference/`に保存します。
実行中のアプリのCPUアーキテクチャに合うMetal版（tar.gz）を取得します。GPU（Metal）とCPUを選べます。
macOSでのアプリ終了時は推論プロセスを終了します。強制終了時の連動終了はWindowsのみです。
Macでの初回取得もアプリの「モデルをダウンロード」から行います。以下のPython準備スクリプトはWindows専用です。
検証が完了するまで新しいファイルを有効にせず、取得や展開の途中で失敗しても既存ファイルは維持します。
やり直す場合は、取得・検証済みのファイルを再利用します。中止した取得途中のファイルは破棄します。
別のアプリから同時に取得しないよう、保存先をロックします。

開発用には、Python 3.11以降でリポジトリのルートから準備する方法も残しています。

Python 3.11以降でリポジトリのルートから実行します。

```powershell
python tools/prepare_local_engine.py
```

llama.cpp b11804のWindows Vulkan版 (zip約37MB) と、2BモデルのQ4_K_M版 (約1.81GB) を
固定URLから取得し、SHA-256を検証します。保存先は
`%LOCALAPPDATA%/com.witenp.ptranslate-desk/inference/`です。

## 開発用のビルド

既存の配布版とは別の設定を使う試作版を作ります。必要な開発環境は[desktop/README.md](../desktop/README.md)を参照してください。

```powershell
cd desktop
npm ci
npm run tauri -- build --debug --config src-tauri/tauri.local-prototype.conf.json -- --locked
```

インストーラーは`desktop/src-tauri/target/debug/bundle/nsis/`に生成します。
試作版のアプリ名は「PTranslate Desk Local Prototype」です。既存版と設定を分離し、自動更新の配布先も設定しません。
同時起動すると共通のショートカットが競合するため、普段使う版を終了してから試してください。

GPUの起動に失敗する場合は設定でCPUを選んでください。自動のCPU切り替えはまだ行いません。

## 構成

- ローカルモードではOIDC認証・翻訳サーバーを使わず、RustでPFML3プロンプトを組み立てる。
- サーバーモードのAPIとPythonでのプロンプト生成は維持する。
- 共通の[入力・期待値](../shared/local-translation-fixtures.json)をPythonとRustのテストから読み、一致を確認する。
- 入力の上限、用語集、文体、過去の訳、ストリーミング表示は既存の画面と同じ規則を使う。
- 推論プロセスは127.0.0.1の一時ポートで待ち受け、起動ごとに生成する認証キーを使う。
  キーはコマンドラインに出さず、認証なしの要求が拒否されることを起動時に確認する。
- 原文・訳文・プロンプトをファイルや子プロセスのログに保存しない。
- Vulkan版でNVIDIAとAMDの両方を扱う。CPUではGPUレイヤーを0にする。
- 推論の並列数は常に1〜64件の数値で指定する。既定は1件。計測すると推奨値が設定欄に入り、保存・再起動後に反映する。
  メモリ容量による自動調整や自動・手動の切り替えは行わない。古い設定の `auto_parallel` は無視し、保存済みの `parallel` を使う。
  デバイスの速度比較は条件をそろえるため1並列で行う。
- 1件あたりのコンテキスト32768トークンを維持するため、総コンテキストは32768×並列数とする。
  並列数を増やすとメモリ使用量が増え、短文1件の応答が速くなるとは限らない。Flash Attentionは有効にする。

## Chrome拡張との連携

Chromeはデスクトップの実行ファイルを中継専用モードで起動する。
中継はWindowsでは名前付きパイプ、macOSではUnixソケットを通じて、同じ利用者が起動したデスクトップに要求を渡す。
モデル・デバイス・メモリ管理・実行枠はデスクトップと共有する。拡張のローカルモードからサーバーへの自動転送は行わない。

1. 最新のデスクトップをインストールし、一度起動してローカル翻訳を設定する。macOSではアプリを「アプリケーション」に移してから起動する。
2. Chrome拡張の設定で「このPCで翻訳」を選び、「接続」を押す。ブラウザーのアプリ起動確認を許可する。
3. デスクトップに表示された連携の確認画面で「登録する」を押す。
4. 拡張の設定に接続完了が表示されるのを待つ。承認後のボタンの押し直しは不要。
   「Chrome連携が見つかりません」と表示された場合は、Chromeをすべて終了して起動し直し、再度確認する。

アプリが開かない場合は、拡張設定の「デスクトップが開かない場合」にあるIDを、デスクトップ設定の
「拡張IDを手動で登録」に入力できる。

専用URLは `ptranslate://register-chrome?extension_id=<32文字のID>`。起動中は既存のアプリへ要求を転送する。
Webサイトからも呼べるため、URLの受信だけでは登録しない。IDとURLの形式を検証し、デスクトップで明示的に承認する。
確認中のIDの差し替え、キャンセル済み要求の再承認は拒否する。受信・承認によって翻訳モードを変更したり、モデルを取得したりはしない。
URLの起動先はWindowsでは通常起動時にユーザー単位で登録し、macOSでは配布するアプリに定義する。

登録はユーザー単位で、管理者権限は不要。後から登録した拡張ID・実行ファイルが有効になる。
実行ファイルを移動した場合や、通常版と試作版を切り替える場合は登録し直す。
Windowsのホスト定義は `%LOCALAPPDATA%/PTranslateChrome/native-host.json`、Chromeの登録先は
`HKCU\Software\Google\Chrome\NativeMessagingHosts\com.witenp.ptranslate`。
macOSのホスト定義は `~/Library/Application Support/Google/Chrome/NativeMessagingHosts/com.witenp.ptranslate.json`。

Windowsのインストーラーからの通常のアンインストールでは、自身のEXEが登録した連携だけを解除する。
自動更新中は登録を維持する。開発版はそのEXEを `--unregister-chrome` 付きで起動すると解除できる。

Chrome連携のパイプやソケットを作れなくても、デスクトップ本体は起動し、サーバー翻訳と本体でのローカル翻訳を利用できる。
連携の設定欄に失敗と再起動の案内を表示し、連携を利用できない状態では登録を変更しない。
Windowsでは同じアプリの二重起動を防ぎ、URLを起動済みのアプリへ渡す。
通常版と試作版など識別子の異なるアプリを切り替える場合は、使う側で連携を登録し直す。

中継の送信待ち行列は256メッセージまで保持し、満杯なら推論応答の読み取り側が非同期で空きを待つ。
混雑を接続失敗として扱わず、応答を欠落させない。Chromeが接続を閉じた場合は待機も含めて中止する。

中継の試験は `cargo test --locked --manifest-path desktop/src-tauri/Cargo.toml` と、
Windows・macOSで `cargo build --locked --features smoke-test --manifest-path desktop/src-tauri/Cargo.toml` の後に
`python tools/test_chrome_bridge.py` を実行する。試験は一時的なホスト定義とモックのパイプまたはソケットを使い、中継の完了・中止を確認する。
Windowsではパイプが占有されている場合の本体起動・失敗通知も確認する。
Chromeの登録・既存設定・実モデルには触れない。
Windowsでは同じビルドで `python tools/test_chrome_registration.py` を実行すると、新規起動・起動中のアプリへのURL転送と、
IDの確認・キャンセル・キャンセル後の承認拒否を確認する。この試験も登録やモデル取得を行わない。

Windowsで実Chromeと取得済みモデルで確認する場合は、`smoke-test`付きビルドの後に、
`python tools/run_extension_local_probe.py --device Vulkan0 --parallel 1` を起動する。
表示されたページで拡張の翻訳を開始する。並列数は `--parallel 4` などで指定できる。
モデル・既存のデスクトップ設定を変更せず、試験終了時にChrome連携の登録も元に戻す。
試験アプリは閉じる操作で常駐するため、終了にはトレイの「終了」を使う。

### Chromeでの手動確認（2026-11-08）

Windows x64・Chrome 156・RTX 4090（Vulkan0）で、実拡張からページ全体の翻訳と原文への復元を確認した。
選択文の小窓が透明になる場合があったため、埋め込み画面の準備完了を確認し、
2秒以内に準備できない場合は別ウィンドウへ切り替える処理を追加した。修正後の選択文翻訳も確認した。
451か所のページ翻訳中に「中止」を押し、未翻訳部分を残して停止すること、
停止後に本文が変わらないこと、中継プロセスが終了することを確認した。
Chromeが登録直後のホストを見つけられない場合は、完全に終了して起動し直すと接続できた。

実アプリへの中継では1件・4件の並列数通知、4本同時の翻訳完了、中止後の再翻訳を確認した。
4並列ではエンジンの `--parallel 4` と総コンテキスト `131072` を確認した。
`python tools/test_extension_live.py --extension-id <拡張ID> --parallel 4` で、
起動中の試験用アプリを相手に中継・並列翻訳・中止後の再翻訳を再確認できる。
この試験は実モデルを使うため通常のCIでは実行しない。
