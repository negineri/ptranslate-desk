v0.9.0-beta.10 は、ボランティア翻訳の試験版です。公式のボランティア枠は引き続き未公開です。

## beta.9 からの変更

- デスクトップと Linux ワーカー CLI が起動する llama-server で、`--cache-ram 0` を指定してプロンプトの RAM キャッシュを無効にしました。長時間のページ翻訳などで、このキャッシュがメモリを使い続ける問題を防ぎます。
- 自分で起動する llama-server や運営の確認用エンジンにも、`--cache-ram 0` の指定を推奨します。

## beta.8 からの変更 (beta.9)

- Linux ワーカーは `ptranslate-worker run --slots 4` のように、1つの資格で複数の翻訳枠を提供できます。既定は1枠です。仲介の1台あたりの上限は `TR_WORKER_MAX_SLOTS` で設定し、既定は64枠です。複数枠の提供には仲介とワーカーの両方を更新してください。
- Chrome 拡張では、登録済みの利用者がボランティア枠でページを訳すとき、空き枠に合わせて区切りを送ります。同じ優先度では実行中のページ翻訳が少ない利用者へ次の空き枠を優先し、所有者への原文の分散も引き続き適用します。
- 直結プールでは `TR_PAGE_SLOTS_PER_USER` と `TR_MAX_ACTIVE_PER_USER` を設定して、同じ利用者のページ翻訳を複数並行で実行できます。
- 4枠の同時処理と、ページ翻訳の100区切りの同時開始をモックで確認しました。本番の処理能力は未計測です。

## beta.7 からの変更 (beta.8)

### Linux サーバー向けのワーカー CLI

- 単体のワーカー CLI `ptranslate-worker` を追加しました。Assets の `PTranslate.Worker_0.9.0-beta.8_linux-x64.tar.gz` に入っている実行ファイル 1 つで動きます。デスクトップアプリ、GUI のライブラリ、Python は要りません。必要なのは Linux x64 (glibc 2.35 以降) と bubblewrap です。
- `ptranslate-worker authorize <提供先のURL> --accept-terms` で認可し、`ptranslate-worker run` で提供を始めます。推論エンジン (llama.cpp b11804、CPU) と承認済みモデルは、初回に自動で取得・検証して起動します。
- 自分で用意した `llama-server` を使う場合は、`--engine-url` (別のサーバー) か `--engine-port` (同じサーバー) を指定します。
- 状態ファイルは以前の Python 版 (`tools/volunteer_worker.py`) と同じ形式なので、同じ `--state` をそのまま使えます。Python 版は移行のために残していますが、今後は使わないでください。手順は[ボランティア翻訳の仕様](https://github.com/negineri/ptranslate-desk/blob/v0.9.0-beta.8/docs/VOLUNTEER_TRANSLATION.md)を参照してください。
- 実際の仲介を相手にしたジョブの処理は、この版で初めて確かめます。

## beta.6 からの変更 (beta.7)

### 1回の原文の上限とコンテキスト

- 1回に送る原文の上限を、クライアントの区切りと同じ1500文字にそろえました (`TR_MAX_CHARS` の既定を4000から1500に変更)。前の訳は原文1500文字・訳4500文字までです。Web・デスクトップ・Chrome 拡張は以前から1500文字ごとに送っているので、使い方は変わりません。
- ローカル翻訳の1件あたりのコンテキストを32768から16384トークンに下げました。1件あたりのメモリが約96 MiB 減り、同じメモリで並列数を増やせます。プロンプト全体の上限 (12000文字) と訳の上限から、1文字1トークンの入力でも収まる量です。根拠は[ローカル翻訳の仕様](https://github.com/negineri/ptranslate-desk/blob/v0.9.0-beta.7/docs/LOCAL_TRANSLATION.md)にあります。
- ワーカーの CLI がリモートの `llama-server` に求めるコンテキストも、1枠あたり16384以上になりました。32768のままでも使えます。
- **サーバー更新前に確認が必要です。** 確認用ジョブのファイルに1500文字を超える原文があると、仲介は起動しません。また、新しいデスクトップのワーカーは1500文字を超える割り当てを断るので、サーバーはデスクトップより先か同時に更新してください。API を直接呼んで1500文字を超える原文を送ると、413 が返ります。

## beta.5 からの変更 (beta.6)

### ボランティア枠の品質検査

- 確認用ジョブは、長い原文だけを使います。`TR_CANARY_MIN_LENGTH` (既定 120。漢字・かな・ハングルは 1 字を 2 と数える) 未満の項目は読み込み時に除きます。短い文では、正しいワーカーでも一語の違いで類似度が大きく下がっていました。
- 照合の数字は、原文と用語集にあるものも許します。それでも違う場合は 1 件では不合格にせず、その件の点を下げます。基準の訳がモデルの誤りで数字を変えることがあるためです。
- 直近 `TR_PROBATION_JOBS` 件 (既定 20) の類似度の平均が `TR_CANARY_MIN_SCORE` (既定 0.93) を下回ったら検疫します。試用の合格と検疫からの戻りにも、この平均を使います。1 件ずつでは見分けにくい小さいモデルや雑な量子化を検出するためです。
- 抜き取りは、URL・メールアドレスと訳す先の文字種だけで判定します。
- **サーバー更新前に確認が必要です。** 確認用ファイルに長い文が 1 件もないと、仲介は起動しません。しきい値は日本語と英語の間の実測で決めた暫定の値です。[照合の規則](https://github.com/negineri/ptranslate-desk/blob/v0.9.0-beta.6/docs/VOLUNTEER_TRANSLATION.md)

## beta.4 からの変更 (beta.5)

### 接続先の設定

- 初期設定、接続先の変更、ワーカーの登録で、サーバーの URL を入れるだけで接続先を設定できるようにしました。ログインの設定はサーバーの `GET /api/client-config` から取得します。取得に失敗した場合は、変更前の接続設定を保ちます。
- **サーバー更新時に前段の設定が必要です。** 認証プロキシで `GET /api/client-config` を認証なしで通してください。nginx と Compose の例を更新しました。

### ボランティア枠

- ログインした利用者向けのマイページを追加しました。ワーカーの状態、規約への同意、月別・累計の貢献量を表示します。新規登録とアカウントの操作は、運営が設定した IdP の画面へ案内します。
- 配信が完了した翻訳から貢献量を推定して記録します。1日の上限と自分の依頼の除外を適用し、品質検疫で取り消します。
- 本人が掲載を選んだ参加者のランキングを、ログインした利用者に表示します。
- 運営用の鍵付きの退会通知で、登録・同意・貢献量・掲載設定を削除します。
- ワーカーの資格を、提供中に所有者の OIDC 認証で自動更新します。更新の認可が失効した場合は提供を止めます。資格の既定の有効期間は7日、上限は30日です。
- Linux のワーカー CLI で、別の端末のブラウザーで初回の認可を行い、画面なしで提供できるようにしました。`--engine-url` で、別のサーバーの `llama-server` に HTTPS で接続することもできます。接続先のモデルの SHA-256 などを、ジョブを受ける前に照合します。
- 本番で有効にするには、認証プロキシの経路、IdP の各フロー、退会通知の設定が必要です。手順は[ボランティア翻訳の仕様](https://github.com/negineri/ptranslate-desk/blob/v0.9.0-beta.5/docs/VOLUNTEER_TRANSLATION.md)を参照してください。

### まだ確認していないこと

- 本番の Authentik での資格の自動更新と退会の連携、リモートの `llama-server` の実機への接続。

## beta.3 からの変更 (beta.4)

- AppImage で、ローカル翻訳のセットアップが「推論エンジンが終了しました」で失敗する問題を修正しました。AppImage に同梱したライブラリを推論エンジンが読み込み、端末の OpenSSL と版が合わずに終了していました。推論エンジンとブラウザーは、AppImage の環境を外して起動します。
- 試験版は自動更新の対象外です。beta.3 の AppImage を使っている場合は、Assetsから beta.4 の AppImage を取得し直してください。

## beta.2 からの変更 (beta.3)

- Ubuntu 24.04以降 (x64) 向けに、`.deb` と AppImage の配布を始めました。Assetsの `_amd64.deb` または `_amd64.AppImage` を使います。
  - `.deb` は `sudo apt install ./PTranslate.Desk_<version>_amd64.deb` で導入します。自動更新には対応していません。新しい版の `.deb` を入れ直してください。
  - AppImage は実行権限を付けて起動します。署名を検証したうえでアプリ内から更新できます。ローカル翻訳の処理を提供する場合は、別途 `bubblewrap` をインストールしてください。
  - Linux の配布物を Release で配るのは初めてです。クリーンな端末での導入と、AppImage の更新はまだ確認していません。

## beta.1 からの変更 (beta.2)

- 登録済み利用者とワーカー所有者を OIDC の `sub` で識別します。改名してもワーカーの登録・参加同意・失効は同じアカウントに残ります。
- **サーバー更新前に前段の設定が必要です。** 認証済みの `sub` を `X-Forwarded-User-Id`、表示名を `X-Forwarded-User` で渡してください。旧版のワーカー状態ファイルに記録がある場合は移行が必要です。[前段と移行の手順](https://github.com/negineri/ptranslate-desk/blob/v0.9.0-beta.2/docs/SELF_HOSTING.md)
- macOS の画面試験で失敗箇所を特定しやすくし、ビルド時の警告を整理しました。

## beta.1 で追加した機能

v0.9.0-beta.1は、翻訳の処理をほかの端末に分担してもらう「ボランティア枠」の仕組みを加えた試験版です。

**公式のボランティア枠はまだ公開していません。** この版で加えた機能は、サーバーの管理者が有効にした場合だけ使えます。

## サーバー

- 翻訳の処理を、登録した端末 (翻訳ワーカー) に割り当てるボランティア枠を追加しました。`TR_POOL_KIND=volunteer` で有効にします。既定は直結 (`direct`) です。
- ワーカーは登録直後に試用を行い、その後も確認用ジョブと抜き取りで検査します。結果が合わないワーカーは検疫します。
- ログインなしで翻訳を始められる匿名の利用を追加しました。`TR_ANON_ENABLED=1` で有効にします。既定はオフです。
- 設定と脅威への対策は[ボランティア翻訳の仕様](https://github.com/negineri/ptranslate-desk/blob/main/docs/VOLUNTEER_TRANSLATION.md)を参照してください。

## デスクトップ

- 設定に「翻訳の処理を提供する」を追加しました。提供先のサーバーに登録した端末で、ほかの人の翻訳をローカルのモデルで処理します。
  - 対応するのはmacOSとUbuntu 24.04以降 (x64) です。Windowsでは提供できません。
  - 処理は権限を制限した別のプロセスで行います。外部電源で動いている間だけ新しい処理を受け、自分の翻訳を優先します。
  - オンにした状態はアプリの起動中だけ有効で、次の起動時はオフに戻ります。
- ボランティア枠を使うサーバーでは、最初の翻訳の前に同意を確認します。
- 匿名の利用を有効にしたサーバーでは、ログインなしで翻訳できます。
- Ubuntu 24.04以降 (x64) で、ローカル翻訳 (CPU) に対応しました。Ubuntu向けのパッケージは配布していません。ソースから `.deb` を作成してください。
- macOSで、空きメモリを実際より少なく見積もり、推奨設定の計測を始められないことがある問題を修正しました。
- 自動翻訳を中断したとき、以前の訳を元に戻すようにしました。
