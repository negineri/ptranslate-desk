# PTranslate Desk (macOS / Windows)

WindowsとmacOSでは、翻訳サーバーを使わない[ローカル翻訳](../docs/LOCAL_TRANSLATION.md)も選べます。
初回にモードを選び、モデルの取得とデバイスの簡易計測を画面から進めます。

Tauri 2 のメインウィンドウをローカルの翻訳モックで試せます。Rust、Node.js、各 OS の
[Tauri の開発に必要なツール](https://v2.tauri.app/start/prerequisites/)を用意してください。Ubuntu では追加で `libdbus-1-dev` が必要です。

macOS は 13 以降に対応します。Mac では Xcode Command Line Tools (`xcode-select --install`) を使います。

Windows は 10 / 11 (x64) 向けです。開発には Rust の MSVC ツールチェーン、Visual Studio Build Tools の
「C++ によるデスクトップ開発」、WebView2 Runtime を用意します。

## Windows で使う

メインウィンドウ、ブラウザでのログイン、ストリーミング翻訳、設定、翻訳ポップアップは macOS と共通です。
refresh token は Windows の資格情報マネージャーに保存します。

ほかのアプリで文を選び、Ctrl+C を 0.5 秒以内に 2 回押すと、マウスの近くに翻訳ポップアップを出します。
設定で Ctrl+Shift+T や任意の組み合わせに変更できます。組み合わせを離すと Ctrl+C を送り、
選んだ文を取得した後にクリップボードの文字列を戻します。管理者権限で動くアプリにはコピー操作を送れない場合があります。
macOS のアクセシビリティ許可は不要です。メインウィンドウを閉じても通知領域に常駐し、トレイの「終了」で終了します。

PowerShell でリポジトリのルートからモックを起動します。本番サーバーには接続しません。

```powershell
python tools/run_desktop_mock.py
```

Windows の NSIS インストーラーを作るには `desktop/` で実行します。

```powershell
npm ci
npm run build
```

`src-tauri/target/debug/bundle/nsis/` にインストーラーを生成します。
Windows 用の設定は Tauri が `tauri.windows.conf.json` から自動で読み込みます。
コード署名は未設定です。CI でも Windows の単体試験、モックでのメインウィンドウ・ポップアップ試験、
インストーラーの作成を行い、成果物 `windows-installer` に保存します。
タグの配布ビルドは最適化したインストーラーを作成し、GitHub Releasesと共通の更新マニフェストへ登録します。
コード署名は付けませんが、更新ファイルにはTauriの更新署名を付けます。
署名ジョブはWindowsのインストーラーを実行しません。詳細は[配布手順](../docs/RELEASING.md)を参照してください。

## サーバーに接続してログインする

### 接続先を選ぶ

ログイン前から操作できる「接続先の設定」でサーバーURL、
OIDC discovery URL、公開クライアントのclient IDを指定します。
「保存して再起動」を押すと設定が反映されます。再起動後、設定したサーバーの利用者でログインしてください。
認証情報は接続先ごとに分離します。
サーバーURLは `https://translate.example.com` のようにパスを付けず指定します。
サーバー・認証基盤もこれから作る場合は[最初から構築する手順](../docs/SELF_HOSTING.md)を参照してください。

### ログインとキーチェーン

アプリを起動して「ログイン」を押すか、メニューバーの「ログイン」を選びます。
OS の既定のブラウザで Authentik にログインし、初回の同意の画面で許可してください。
利用できるアカウントは、接続先の管理者がAuthentikで設定します。
ログイン後、メインウィンドウに Authentik の利用者名が表示されます。

macOSでは、ログイン状態を保つための認証情報をキーチェーンに保存します。起動時やログインの更新時に、
「PTranslate Deskがキーチェーン内の “com.witenp.ptranslate-desk” に保存されている機密情報を
使用しようとしています」という確認が表示されることがあります。
アプリ名と保存先が上記と一致することを確認し、キーチェーン「ログイン」のパスワードを入力して
**「常に許可」** を押してください。通常はMacにログインするときのパスワードです。
パスワードはmacOSの確認画面に入力します。「常に許可」は、この認証情報へのアクセスを許可して
以後の確認を省くための操作です。アプリの更新や差し替え後は、再び確認されることがあります。
キーチェーンとMacのログインパスワードの関係は[Appleの説明](https://support.apple.com/ja-jp/guide/keychain-access/kyca2612/mac)も参照してください。

認証は設定した公開クライアントのAuthorization Code + PKCE (S256) です。authorize・token・revoke の URL は discovery から取得し、
scope は `openid profile offline_access` に限定します。`email` は要求しません。

access token は Rust のメモリ、refresh token は macOS のキーチェーン (Windows は資格情報マネージャー、
Linux は Secret Service) に保存します。トークンを画面・ログ・設定ファイルへ渡しません。
起動時と有効期限の 1 分前、API の 401 応答時に更新します。更新に失敗したときや 403 を受けたときは、
ログインし直します。403 の HTML は JSON として読みません。
ログアウトすると端末の資格情報を削除し、discovery の revoke URL でも無効化します。

## モックで起動する

リポジトリのルートで、次の 1 コマンドを実行します。

```sh
python3 tools/run_desktop_mock.py
```

画面をビルドし、翻訳エンジンのモックと翻訳サーバー、メインウィンドウを起動します。
「モックにログイン」を押し、原文を入力すると、1 秒後にモックの訳が届き始めます。
モックの訳は `[ja] Hello` のように、言語の印と原文を返します。
メインウィンドウを閉じてもメニューバーに常駐します。メニューバーの「終了」か ⌘Q でアプリを終了すると、
起動したサーバーとモックも終了します。8002 番ポートが使用中なら終了します。

メインウィンドウでは、自動翻訳、⌘Enter での手動翻訳、中止、空にする、訳のコピー、言語の入れ替え、
文体、文脈、用語集を使えます。

## 翻訳と端末の設定を切り替える

メインウィンドウの「翻訳」「設定」で画面を切り替えます。「設定」には接続先、ショートカットなどのデスクトップの設定、
macOSのキーチェーンの説明があります。画面上部にバージョンと更新操作、利用者名とログイン・ログアウトをまとめています。
バージョン表示を押すと更新の確認やインストール、利用者名を押すとログアウトを操作できます。ログイン前も設定を開けます。タブを切り替えても入力中の原文と訳文は残ります。
メニューバーから設定を開くと設定タブへ移り、ポップアップから原文を引き継ぐと翻訳タブへ戻ります。

## 選んだ文を翻訳ポップアップで訳す

1. 「モックにログイン」し、メインウィンドウの「デスクトップの設定」を開きます。
2. 「アクセシビリティの設定を開く」を押し、macOS の「プライバシーとセキュリティ →
   アクセシビリティ」で「PTranslate Desk」を許可します。開発用の実行ファイルで試す場合は、実行している
   アプリまたは端末に許可が必要な場合があります。許可後はアプリを再起動します。
3. ほかのアプリで文を選び、⌘C を 0.5 秒以内に 2 回押します。コピーされた文をマウスの近くの
   翻訳ポップアップで訳し、届いた分から表示します。

設定で ⌘⇧T に切り替えることもできます。この場合はアプリが ⌘C を送り、選んだ文を取得した後、
元のクリップボードの文字列を戻します。選択が無いときやコピーできないアプリでは、メインウィンドウにエラーを表示します。
⌘C を 2 回押す方式では、自分でコピーした文をそのまま使います。

翻訳ポップアップには「コピー」「メインウィンドウで開く」「閉じる」があります。Esc、外のアプリへのフォーカス移動、
閉じるボタンで消え、翻訳サーバーへの接続も切ります。メインウィンドウで開くと原文を引き継いで翻訳します。
言語・文体・用語集はメインウィンドウと共通です。翻訳ポップアップとメインウィンドウの翻訳は同時に流さず、新しい翻訳を優先します。

メニューバーには「メインウィンドウを開く」(未ログインなら「ログイン」)、「ショートカットを一時的に止める」、
「設定」「ログアウト」「終了」があります。未ログイン時はアイコンも変わります。
メインウィンドウを閉じた後は、メニューバーか Dock のアイコンから開けます。

ショートカットによる選択文の取得は、macOS と Windows 向けに実装しています。

## 個別に起動する

1. リポジトリのルートで翻訳モックを起動します。

   ```sh
   python3 tools/mock_plamo.py --port 18082
   ```

2. 別の端末で、リポジトリのルートからサーバーを起動します。

   ```sh
   TR_LISTEN_HOST=127.0.0.1 TR_LISTEN_PORT=8002 \
     TR_UPSTREAM_URL=http://127.0.0.1:18082/v1/completions python3 -I server/translator.py
   ```

3. さらに別の端末でメインウィンドウを起動します。

   ```sh
   cd desktop
   npm ci
   PTRANSLATE_MOCK=1 npm run dev
   ```

4. 「モックにログイン」を押し、原文を入力します。「ログアウト」でモックのセッションを終了します。

モック起動では `PTRANSLATE_MOCK=1` を渡します。この場合だけ接続先を `127.0.0.1:8002` に固定し、
認証プロキシの代わりに Rust 側でモック利用者のヘッダーを付けます。モックは OS の資格情報に触れません。
メインウィンドウは Web 版の画面と翻訳モジュールから生成します。言語・文体・用語集・自動翻訳の設定は、
OS 標準のアプリ設定ディレクトリにある `settings.json` に保存します。

## Mac のアプリをビルドする

`desktop/` で次を実行します。

```sh
npm ci
npm run build
```

`src-tauri/target/debug/bundle/macos/PTranslate Desk.app` と
`src-tauri/target/debug/bundle/dmg/` 内の dmg が生成されます。
既定ではデバッグビルドになり、バージョンは `0.0.0-dev` です。
配布用はHEADに `v*` タグを付けたうえで、明示的に `npm run build:release` を実行します。
配布バージョンはタグから取得し、設定ファイルの書き換えは不要です。
配布版は固定の自己署名証明書を使います。以前の署名から切り替える最初の1回は、アクセシビリティの許可を再登録してください。
Developer ID の署名と公証はしていません。
タグからの配布はApple Silicon・Intel共通のuniversal dmgです。
Releaseの作成、更新署名のsecrets、タグからのバージョン取得は [配布手順](../docs/RELEASING.md) を参照してください。
アプリを単独で起動すると、設定したサーバーにログインできます。

ビルド済みのアプリをモックとまとめて起動するには、リポジトリのルートで実行します。

```sh
python3 tools/run_desktop_mock.py --app 'desktop/src-tauri/target/debug/bundle/macos/PTranslate Desk.app'
```

開発用の実行ファイルだけを作る場合は、次を実行します。

```sh
node build.mjs
cargo build --locked --manifest-path src-tauri/Cargo.toml
```

## Mac のメインウィンドウ・翻訳ポップアップ・常駐を自動で試す

リポジトリのルートで実行します。Mac の GUI セッションが必要です。

```sh
python3 tools/run_desktop_mock.py --smoke-test
```

実際の WebView と Rust の通信を使って、モックへのログイン、53 言語の読み込み、自動翻訳、
ストリーミング、訳のコピー、中止、空にする、ログアウトを確認します。
さらにショートカットの登録と変更、クリップボード取得から翻訳ポップアップを出す処理、翻訳ポップアップの逐次翻訳、
Esc とフォーカス移動での中止、メインウィンドウへの引き継ぎ、メインウィンドウを閉じた後の常駐、メニュー操作を試します。
⌘C を 2 回押す判定は Rust の単体試験でも確認します。
OS の実際のキー監視と、ほかのアプリへのコピーキー送信は、アクセシビリティを許可して手動でも確認してください。
設定は試験専用の一時ディレクトリに保存し、原文と訳を保存しないことも確認します。
試験後に元のクリップボードの文字列を戻します。
試験用の操作は `smoke-test` フィーチャーを有効にしたビルドだけに入ります。
