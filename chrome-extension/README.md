# PTranslate for Chrome (Chrome 拡張)

ブラウザで読んでいるページの文を、PTranslate のサーバーまたはこのPCで訳す Chrome 拡張です。
サーバーモードはChrome 120以降と、EdgeなどのChromium系ブラウザで動きます。
このPCで翻訳する連携はWindows x64のChrome向けです。

- ページで文を選んで右クリック →「PTranslate で翻訳」、またはショートカット (既定は Alt+Shift+T) で、
  選んだ文の近くに訳を出します。PDF のビューアーや埋め込み画面を読み込めないページでは、小さいウィンドウで開きます
- ページ全体を訳せます。右クリック →「PTranslate でこのページを翻訳」、ショートカット (既定は Alt+Shift+P)、
  または拡張アイコンの左クリックから使います (下の「ページ全体の翻訳」)
- 接続後はアイコンの左クリックでページ全体を翻訳します。設定はアイコンを右クリックして「設定」から開きます。
  初回インストール直後は設定を開き、未設定・未接続の左クリックでも設定へ案内します
- 区切り (`splitText`)、訳す先の自動 (`guessTarget`)、用語集 (`parseGlossary`)、SSE の読み取り (`translateChunk`) は
  Web と同じ `server/static/translation.mjs` を使います

## 使い方

1. [GitHub Releases](https://github.com/negineri/ptranslate-desk/releases)の `PTranslate.Chrome_` で始まるZIPを展開し、
   [導入手順](../docs/CHROME_EXTENSION_RELEASE.md)に沿って読み込みます。ストアでの配布はまだしていません
2. 初回導入で開く設定（またはアイコンの右クリック→「設定」）でサーバーURL (例: `https://translate.example.com`、パスなし) を入れ、「接続」を押します。
   そのサーバーへの接続の許可を求められるので、許可します
3. 同じブラウザで Web版 (サーバーURLのページ) にログインしておきます。「ログインしていません」と出たら、
   「Web版を開いてログイン」からログインし直します

文体・原文の言語・訳す先・用語集は拡張の設定で決めます。ショートカットは `chrome://extensions/shortcuts` で変えられます。

## ページ全体の翻訳

- 進捗ポップアップは幅260pxの2段にまとめ、状態は「準備中」「翻訳中」「完了」などに短く表示します。
  完了後の短い追加翻訳では、準備中・完了の表示が点滅しないようにします。
  翻訳先は設定で変更します。初期値は日本語で、保存済みの設定は引き継ぎます。
- 段落 (ブロック要素) ごとに文を集め、訳を元の位置に書き込みます。右上のバーに進み具合が出て、
  「中止」「原文に戻す」ができます。翻訳中・完了後も文章の変更を監視し、チャンネル切り替えや新着の文章を自動で訳します。
  「中止」または「原文に戻す」で監視も止めます。バーを閉じるだけでは監視は続きます。
  訳し終えた後にもう一度呼ぶとバーを出し直し、原文に戻した後なら訳し直します
- 画面に見えている箇所から順に、接続先が通知する数まで並列に訳します。ページ途中までスクロールしてから開始した場合も、表示中の箇所を先に送ります。文字の位置を、画面と祖先のスクロール領域で切り取って判定します。
  見えている箇所の中では、記事・メッセージ (`article`・`role="article"`)、メイン領域 (`main`・`role="main"`)、
  サイドバーなどの順で訳します。スクロールや画面サイズの変更後は、新しく見えた未翻訳の箇所を優先します。送信済みの要求は中断せず、完了後に次を選びます。
  同じ箇所を長さで区切った場合は順に訳し、直前の区切りの訳を手がかりに送ります。
  別の箇所には、送信時点で最後に完了した箇所の訳を手がかりに送ります。最初に同時送信する箇所にはまだ完了済みの訳がありません。
  サーバーの上限は既定で1人2本です。チャンネル切り替え直後など、古い要求の枠が残っていて 429 が返る場合は、
  「前の翻訳の終了を待っています」と表示し、間隔を延ばしながら最大 60 秒待って再試行します。
  待機中も「中止」やチャンネル切り替えで古い要求を止められます。ほかのエラーは再試行しません
- 訳す先の自動 (日本語 ⇄ 英語) はページ全体の文で決めます。数字や記号だけの箇所は送りません。
  中国語や ASCII の外国語を取りこぼさないよう、言語の推測で段落を省くことはしません。
  訳す先と同じ言語の文章も送るため、混在したページでは処理時間が増える場合があります
- `display: contents` の見出しなど、要素自身に箱がなくても表示されている文字は訳します。
  CSS の変更で後から表示された文章も対象にします
- コード (`code`・`pre`)、入力欄、編集できる欄、`translate="no"`・`class="notranslate"` の要素、見えていない要素は訳しません。
  読み上げ用の見出しなど、CSSの `clip`・`clip-path: inset(...)` で全体を隠した文字も除きます
- リンク・ボタン・強調などの内外は別々に訳し、文字を元の要素の中に戻します。文章が細かく分かれるため、文脈が途切れる場合があります
- 1 回の処理で訳すのは最大 3,000 か所です。上限を超えた場合は、訳していない件数を完了時に表示します
- 古い本文が消えた場合は要求を中断し、新しい本文へ切り替えます。サイトが文字ノードを再利用しても古い訳は書き込みません。
  原文への復元でも、サイトが書き換えた文字を古い本文で上書きしません
- open Shadow DOM 内の文章も訳し、内部の文章変更や後から作られる境界を監視します。
  iframe・closed Shadow DOM 内の文章は訳しません。ページ全体の再読み込みや別ページへの通常の移動では、もう一度翻訳を開始してください
- 処理は `page-content.js` (ページに注入する content script) と `page-task.mjs` (background) です。
  content script は `page-translate` の port で段落の一覧を background に送り、訳は background が API を呼んで返します。
  この port はタブの一番上の枠の、この拡張の content script からだけ受けます

## 認証と通信

拡張は自分ではログインせず、Web版のログイン (認証プロキシの Cookie) を使います。
そのため IdP (Authentik・Pocket ID) とサーバーの設定を変える必要はありません。

- API は background (service worker) からだけ呼びます。拡張に許可されたサーバーへの要求には Cookie が付き、
  ページの CORS の制限も受けません。訳の画面 (`popup.html`) はページの中の枠 (iframe) で動くため、
  直接は呼ばずに `chrome.runtime` の port で background に頼みます (`transport.mjs` → `relay.mjs`)
- 呼べるのは `GET /api/config` と `POST /api/translate` だけです (デスクトップの `start_request` と同じ)。
  port は拡張自身の画面からしか受けません
- 認証プロキシのログイン画面への転送は追わず (`redirect: "manual"`)、401・403 と同じくログインしていないとして扱います
- 中止は port を閉じて伝えます。background が接続を閉じ、サーバーが翻訳エンジンを止めます (SPEC 5.4)。
  120 秒なにも届かなければ時間切れにします (SPEC 5.2)
- サーバーURLは HTTPS だけです。開発用に `http://127.0.0.1`・`http://localhost` は通します

## 保存するもの

`chrome.storage.local` に翻訳する場所・サーバーURL・言語・文体・用語集だけを保存します。ページ全体の翻訳の原文と訳は、そのページの中だけに置きます。
選んだ文は訳の画面へ渡すあいだだけ `chrome.storage.session` (メモリ上、ブラウザを閉じると消える) に置き、
訳の画面が読んだらすぐ消します。原文は選択したサーバーまたはこのPCのデスクトップへ送り、訳を受け取ります。

## 開発

拡張は `node chrome-extension/build.mjs` で `chrome-extension/dist/` に組み立てます
(Web の `translation.mjs`・見た目・ロゴを写します)。`chrome://extensions` でデベロッパー モードを有効にし、
「パッケージ化されていない拡張機能を読み込む」で `chrome-extension/dist` を選びます。
ソースを変えたら組み立て直し、拡張と翻訳対象のページを再読み込みします。

モックの翻訳エンジンで試すときは、リポジトリのルートで次を実行します。

```sh
python3 tools/run_extension_mock.py
```

モック・翻訳サーバー (127.0.0.1:8002)・認証プロキシの代わり (127.0.0.1:8003) を起動します。
認証プロキシの代わりは開発用の利用者名を `X-Forwarded-User` に付けて中継するだけなので、開発の端末でだけ使ってください。
拡張の設定のサーバーURLには `http://127.0.0.1:8003` を入れます。
`http://127.0.0.1:8002` を入れると、ログインしていないときの表示を試せます。

試験はリポジトリのルートで実行します。

```sh
npm ci --prefix chrome-extension --ignore-scripts
node chrome-extension/build.mjs
node --test chrome-extension/tests/*.test.mjs
```

## このPCで翻訳（Windows x64）

デスクトップのローカルモデルを利用できる。[設定手順](../docs/LOCAL_TRANSLATION.md#chrome拡張との連携)を参照。
拡張にモデルをダウンロードする必要はない。デスクトップはローカルモードで起動しておく。
設定で「このPCで翻訳」を選び「接続」を押すと、必要な登録と接続確認をまとめて行う。
開いたデスクトップで登録を承認すると、設定に接続完了を表示する。IDの手入力や、承認後のボタンの押し直しは不要。
接続済みなら登録確認を開き直さず接続を確かめる。
専用URLからアプリを開くため、最新版をインストールして一度起動しておく。開けない場合はIDの手動登録も利用できる。
モデルの取得・デバイス・推論の並列数はデスクトップ側で管理し、既定では空きメモリに合わせて自動調整する。

接続先の `/api/config` の `concurrency` に応じてページ翻訳を並列に実行する（拡張側の保護上限は64件）。
通知のない古いサーバーでは1件にする。background内の実行枠は同じ接続先を使うタブと翻訳画面で共有し、
デスクトップとの競合は接続先側で調停する。ローカル接続失敗時にサーバーへ送信することはない。
